# Saved review run compatibility

`RunStore.saveState` writes `stateVersion` into each run's `state.json`.
The first version is 1. Files saved before versioning existed also mean
version 1. The version belongs to the saved format, independently of the
package version. The engine validates the version before reading the run's
fields or loading its bookkeeping.

`packages/engine/src/run/state-version.ts` holds the ordered, forward-only
State adaptations. The list starts empty. Its first entry converts version
1 to version 2, its next entry converts version 2 to version 3, and so on.
Loading applies each required step before validating the current contract.
Loading alone never rewrites the saved file; the next normal save writes
the current version.

When changing the saved state format:

1. Append one State adaptation for the next version. Preserve every earlier
   step, and avoid mutating the input. The current version follows the list's
   length automatically. Extend the adaptation boundary if the change also
   requires converting other run files before the controller reads them.
2. Add a representative saved `v<N>.json` example to
   `packages/engine/test/run/fixtures/`. Keep all earlier examples, including
   `unversioned.json`. Examples should contain the actual old format, rather
   than being regenerated by the current serializer.
3. Update the new-save version expectation in `test/run/store.test.ts`.
   Run the store and `test/state/saved-state.test.ts` tests: every saved example
   must load and resume through the pipeline. Add behavior checks for the
   fields or progress the new adaptation preserves.
4. Run the newer-version manager test to check rollback behavior remains safe.

A newer state version raises `NewerRunStateError` and cannot create a run
controller or resume work. Startup skips it without saving a failed state.
When the saved fields still fit the older display contract, the run list and
run detail expose a paused view with an error notice naming the saved state
version and asking the owner to upgrade. This view is never written back.
If the newer format cannot be displayed at all, loading reports the same
version error and the list logs why it skipped that run. No backward
State adaptations are performed; all saved files remain untouched.
